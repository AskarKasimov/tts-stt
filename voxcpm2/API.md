# VoxCPM2 HTTP API

Этот сервис использует исходный код [OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM)
из коммита `f772e498a45fbb5fb8e13fbf9b9c48be9fe33e69`. На Linux ARM64
образ использует CPU-версию PyTorch, на Linux x86_64 — сборку CUDA 12.8.
CPU-сборка проверена на Linux ARM64.

Из корня этого репозитория:

```bash
docker compose up -d --build voxcpm2
curl http://localhost:8001/health
curl -X POST http://localhost:8001/synthesize \
  -H 'Content-Type: application/json' \
  -d '{"text":"Привет, мир!"}' --output speech.wav
```

`POST /synthesize` принимает JSON с полями `text` (обязательно), `cfg_value`
(по умолчанию 2.0), `inference_timesteps` (20), `seed` (510) и
`use_reference` (boolean, по умолчанию `true`).
Ответ — `audio/wav`. Веса `openbmb/VoxCPM2` загружаются при старте и
сохраняются в Docker volume `voxcpm2-cache`. На CPU синтез может занимать
значительное время.

`GET /health` остаётся liveness-проверкой процесса. `GET /ready` возвращает
503 во время загрузки и после ошибки инициализации, 200 — после загрузки
модели. Стартовый синтез не
выполняется; первый запрос может выполняться дольше из-за первичной
инициализации inference. Пользовательский синтез до готовности возвращает 503.

Модель всегда загружается в стандартном eager-режиме. Настройки генерации
задаются в теле каждого HTTP-запроса и не требуют изменения окружения или
перезапуска сервиса. Время загрузки записывается в лог.

## Референс голоса

При `use_reference=true` сервис автоматически создаёт референс из фиксированной
фразы для комбинации `seed`, `cfg_value` и `inference_timesteps`, затем сохраняет
WAV в постоянном кеше. Следующие запросы с той же комбинацией используют этот
файл; при смене параметров создаётся отдельный референс. `use_reference=false`
пропускает создание и использование референса.

При `use_reference=true` первый запрос для новой комбинации `seed`, `cfg_value`
и `inference_timesteps` сначала озвучивает фиксированный текст без референса:

> Давайте внимательно разберём задачу. Сначала определите, что уже известно и какой результат нужно получить. Затем выберите подходящий способ решения и объясните свой выбор. Если возникнут сомнения, вернитесь к условию, проверьте каждый шаг и спокойно продолжайте работу.

Полученный mono PCM16 WAV сохраняется в `/model-cache/voices/`, внутри существующего
volume `voxcpm2-cache`. Затем текст запроса озвучивается с `reference_wav_path` на этот
WAV. Ответ содержит только запрошенный текст. Первый запрос требует двух генераций;
последующие используют готовый референс, в том числе после перезапуска контейнера.
Путь можно изменить через `REFERENCE_CACHE_DIR`; альтернативный каталог также должен
находиться в постоянном volume.

Ключ кэша учитывает также `MODEL_ID`, фиксированный текст и версию алгоритма кэша.
Значения CFG `2` и `2.0` используют один файл. При замене весов под тем же `MODEL_ID`
нужно удалить соответствующие референсы из volume или повысить версию кэша в коде.
Генерация и сохранение защищены общей блокировкой модели (один процесс Uvicorn);
готовый файл публикуется атомарно. Повреждённый WAV пересоздаётся при обращении.
Ошибки создания референса возвращают 500; частичный новый файл не сохраняется.

При создании референса `retry_badcase=false`, поэтому модель не заменяет выбранный seed
при повторе. Для целевого текста повторы остаются включены; фактический seed каждого
фрагмента записывается в лог. Это не проверка произношения и качества эталона: первый
сгенерированный корректный WAV закрепляется как голос. Он может отличаться от образца,
полученного с тем же seed на другом оборудовании.

Для обычного синтеза без подготовки и использования референса передайте
`use_reference=false`. В этом режиме разрешён `seed=null` для случайной генерации;
при `use_reference=true` значение `seed=null` возвращает 422.

```bash
curl --fail --show-error http://localhost:8001/synthesize \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сначала прочитайте условие и объясните решение.","seed":510,"cfg_value":2,"inference_timesteps":20,"use_reference":true}' \
  --output reference-510.wav

curl --fail --show-error http://localhost:8001/synthesize \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сначала прочитайте условие и объясните решение.","seed":510,"cfg_value":2,"inference_timesteps":20,"use_reference":false}' \
  --output plain-510.wav
```

После обновления достаточно пересобрать `voxcpm2` командой запуска выше, сохранив
volume. На GPU используйте оба Compose-файла. При необходимости прогрейте голос
отдельным запросом с выбранными параметрами до первого обращения пользователей.
Изменение параметров и переключение
`use_reference` через HTTP не требуют новых pull или перезапуска.

## Длинный текст

`POST /synthesize` принимает до 10 000 символов. До 500 символов включительно
используется обычная генерация с сохранением внутренних пробелов текста.
Более длинный текст сервис делит на части до 500 символов (предпочтительно
по предложениям, затем по словам), последовательно озвучивает каждую и
возвращает один WAV с паузами по 150 мс между частями. Если одно слово длиннее
500 символов, оно делится на части. Заданный `seed` используется для каждой
части. При `use_reference=true` один референс используется для всех частей.
Запрос выполняется синхронно и может быть долгим.

```bash
curl -X POST http://localhost:8001/synthesize \
  -H 'Content-Type: application/json' \
  -d '{"text":"Длинное объяснение для студента. Следующее предложение."}' \
  --output long-speech.wav
```

Пустой текст или более 10 000 символов возвращают 422. WAV возвращается только после генерации
всех частей; при сбое частичный аудиофайл не выдаётся.

## Признаки референса

`VOXCPM_REFERENCE_CACHE_SIZE` задаёт размер LRU в памяти процесса: 4 по
умолчанию, допустимо 0–16, 0 отключает кеш. Ключ включает экземпляр/идентичность
модели, SHA-256 содержимого WAV, device, dtype и версию reference-only подготовки.
Повторное использование пути с изменившимися байтами вызывает miss. При
перезагрузке модели ссылки на прежние записи освобождаются. Признаки не
сериализуются на диск; тензоры отделены от autograd, каждый вызов получает
изолированную копию. Кодирование и генерация защищены общей блокировкой.
Public `VoxCPM.generate`/`generate_streaming` принимают `prompt_cache`;
нормализация, seed и WAV badcase retries остаются в `core.py`.

## Потоковый синтез

`POST /synthesize/stream` принимает тот же JSON, в том числе текст до 10 000
символов, и возвращает `application/x-ndjson` без Content-Length, с
`Cache-Control: no-store` и `X-Accel-Buffering: no`. Пример:

```bash
curl --no-buffer --fail http://localhost:8001/synthesize/stream \
  -H 'Content-Type: application/json' -d '{"text":"Объясните ход решения."}'
```

```json
{"type":"start","version":1,"sample_rate":48000,"channels":1,"encoding":"pcm_s16le"}
{"type":"audio","seq":0,"data":"AAAAAA=="}
{"type":"end","chunks":1,"samples":2}
```

Sample rate берётся из модели (целое 8000–192000). Данные — raw mono PCM16
little endian, не самостоятельные WAV. `seq` начинается с нуля и непрерывен;
`end.samples` включает паузы 150 мс между частями длинного текста. Один `start`,
один терминальный `end` либо `{"type":"error","code":"SYNTHESIS_FAILED"}`;
детали ошибок остаются в логах. Пустой результат/NaN/Inf — ошибка, амплитуда
ограничивается перед PCM16-конвертацией. Нельзя считать EOF без `end` успехом.
Валидация JSON возвращает 422; конфигурационные ошибки до открытия — 503.

PCM делится на блоки максимум 64 КиБ; очередь producer→HTTP — максимум 8
блоков, decoded PCM за весь запрос — максимум 64 МиБ. Строка значительно
меньше лимита 256 КиБ. Чтение сети не обязано совпадать с границами строк.
Ожидание свободного места и зависший ASGI send ограничены 5 секундами.
Disconnect отменяет producer при ожидании lock/очереди и между чанками,
токенами и шагами diffusion; активное ядро GPU заканчивается перед проверкой
отмены. Генератор закрывается, model lock освобождается в finally. Финальный
network drain не держит модель. На разрыв транспорта финальный error может
не доставиться; такой поток потребитель обязан отвергнуть.

Streaming всегда задаёт `retry_badcase=false`, потому что отправленный звук
нельзя откатить. WAV сохраняет retries. До слепого сравнения качества streaming
не следует включать в backend по умолчанию. Backend release gate:
`BACKEND_TTS_STREAMING_ENABLED=false`; провайдерная ручка доступна дополнительно.

## Метрики и выпуск

`/metrics` сохраняет `speech_*`: stream учитывается один раз по завершении,
выходное аудио/символы — только после успешного `end`; частичный поток не
попадает в успешный объём. Дополнительные метрики: `voxcpm_model_wait_seconds`,
`voxcpm_reference_build_seconds`, `voxcpm_generation_seconds`,
`voxcpm_reference_cache_total{outcome="hit|miss"}`,
`voxcpm_stream_ttfa_seconds`, `voxcpm_streams_total{outcome="success|error|interrupted"}`,
`voxcpm_badcase_retries_total`. TTFA провайдера измеряет первый поставленный
в transport-очередь PCM; сквозной TTFA измеряется отдельно в браузере. Labels
не содержат текстов, seed, хешей голоса и session ID.

Порядок: TTS с 20/off → backend со streaming=false → frontend с WAV fallback →
закрепление серверного голоса → отдельные измерения compile/cache/10 →
сквозная проверка раннего звука через reverse proxy → включение прошедших
приёмку настроек. CPU fake-модели не доказывают CUDA-ускорение или качество.
10–15 шагов ранее теряли вопросительную интонацию; default остаётся 20 до
новых замеров и прослушивания двумя русскоязычными слушателями. Откат:
выключить backend streaming, вернуть 20 и optimize=off, пересоздать сервисы
и дождаться `/ready`. Закреплённый голос и старые volume сохраняются.

На NVIDIA-сервере запускайте оба Compose-файла из корня этого репозитория:

```bash
docker compose -f docker-compose.yaml -f docker-compose.gpu.yaml up -d --build
```

Для локальной проверки API без загрузки весов:

```bash
cd voxcpm2
SETUPTOOLS_SCM_PRETEND_VERSION=2.0.3 uv sync --extra api --extra api-test
uv run --no-sync python -m pytest -q tests/http
```
