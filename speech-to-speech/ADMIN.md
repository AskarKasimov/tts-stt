# Требования к серверу для Qwen3-Omni

Этот блок предназначен администратору, который подготавливает сервер.
Исполнитель запускает сервис по [основной инструкции](README.md).

## Поддерживаемый профиль

| Компонент | Требование |
| --- | --- |
| ОС | Ubuntu 24.04 LTS, Linux x86_64 |
| GPU | Та же NVIDIA GPU 80 ГБ, на которой работают STT/TTS; compute capability от 8.0 и BF16, без MIG |
| Номер GPU | 0 на однокарточном сервере; минимум 75% свободной VRAM перед запуском Qwen |
| RAM | 128 ГБ |
| Диск | 150 ГБ свободно для Docker, весов и результатов проверки |
| Драйвер NVIDIA | 580.95.05 или новее |
| ПО хоста | Docker Engine, Docker Compose с `up --wait --wait-timeout`, NVIDIA Container Toolkit, Python 3, Git, curl |
| Права исполнителя | Запуск Docker без `sudo`, запись в каталог репозитория |
| Исходящий доступ | GitHub, Docker Hub, PyPI, Hugging Face и используемые ими хранилища артефактов |
| Входящий доступ | SSH для установки; TCP 8002 для клиентов API по правилам сети организации |

По умолчанию используется GPU 0 — та же единственная карта, которую существующий
`docker-compose.gpu.yaml` передаёт GigaAM/VoxCPM2 через `gpus: all`.
Qwen запускается рядом с ними в отдельном Compose-проекте; `run.sh stop`
останавливает только Qwen и его API. STT/TTS не останавливаются и не пересобираются.

В `deploy.yaml` доли памяти стадий Qwen равны 0,50 / 0,15 / 0,05 — суммарно
70% карты. Оставшиеся 30% — плановый бюджет STT/TTS и общего резерва.
Это настройки движков, а не аппаратная изоляция памяти. Перед запуском нужно
75% свободной VRAM; при меньшем объёме проверка прекращает запуск до загрузки
модели. Пик одновременной работы трёх моделей должен быть измерен на сервере.
Общая политика проверок хранится в `gpu_policy.json`; название модели GPU
не ограничивается только A100/H100.

В контейнере закреплены CUDA 13.0.2, vLLM 0.32.0, source commit vLLM-Omni
и версии Python-пакетов. CUDA Toolkit на хосте отдельно не требуется.
Этот комплект использует один программный стек; поддержку CUDA 12.x он
не заявляет. Драйвер должен соответствовать требованиям этого образа.

Инструкции производителей для подготовки хоста:

- [Docker Engine для Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
- [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

## Проверка перед передачей исполнителю

Откройте каталог `speech-to-speech` переданного репозитория и выполните:

```bash
./run.sh check
```

Команда автоматически проверяет карту, драйвер, свободную память, диски,
доступ к Docker и свободные порты. Доступ к GPU из контейнера отдельно
проверяется самой установкой перед скачиванием модели.

Исполнитель получает подготовленный сервер и репозиторий с нужным коммитом.
Далее ему достаточно `./run.sh install`; выбор версий и настройка GPU
в его последовательность действий не входят.

## Дополнительные настройки

При нестандартной сетевой схеме, размещении кеша на отдельном диске или
использовании другой физической карты администратор заранее создаёт `.env`
по `.env.example`. Настройки должны быть проверены до передачи сервера.
Описание параметров и дополнительных команд: [OPERATIONS.md](OPERATIONS.md).

## Статус приёмки

Сборка образа, зависимости, 38 тестов и HTTP-тракт с заглушкой проверены.
Реальный запуск модели и общий пик VRAM Qwen/STT/TTS пока не измерены.
`install` выполняет реальную проверку после запуска. При ошибке серверный
прогон считается неуспешным; текущий PR остаётся черновиком до GPU-приёмки.
