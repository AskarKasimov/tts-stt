# Qwen3-Omni: голосовой вопрос → голосовой ответ

Эта папка содержит отдельный сервис для **одной NVIDIA A100 80 ГБ или H100
80 ГБ**. Модель слышит вопрос, формирует ответ и озвучивает его. GigaAM и
VoxCPM2 для этого запуска не нужны.

Используется готовая версия Qwen3-Omni от Intel с квантованием **INT4 W4A16**:
основная языковая часть сжата до 4 бит, голосовые части сохранены в BF16.
Веса занимают около **26,3 ГБ**. Самостоятельно квантовать модель не нужно.
Версии модели, исходников и базового Docker-образа закреплены в файлах проекта.

**Статус:** Docker-образ собран локально; проверены зависимости, конфигурация
стадий и HTTP API без весов модели. Запуск модели на A100/H100 здесь ещё не выполнялся.
Поддержка выбранного checkpoint описана авторами vLLM-Omni, однако это не
заменяет серверный прогон и замер VRAM. Для приёмки предусмотрена проверка
настоящего аудиовыхода напрямую и через HTTP-обёртку.

## 1. Подготовьте сервер

Нужно:

- Linux x86_64, предпочтительно Ubuntu 24.04 LTS.
- Одна свободная A100/H100 **80 ГБ**, без разделения MIG.
- RAM 128 ГБ; свободное место: 40 GiB под веса и 40 GiB под Docker.
  Если это один диск, нужно минимум 80 GiB свободно. Лучше выделить 150 ГБ.
- Драйвер NVIDIA **580.95.05 или новее**: в нашем образе CUDA 13.0.2.
- Docker Engine, плагин Docker Compose, NVIDIA Container Toolkit, Python 3, Git.
- Доступ сервера к GitHub, Docker Hub, PyPI и Hugging Face.

Установку драйвера и компонентов Docker нужно закончить **до запуска**.
Инструкции для администратора:
[Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/),
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
CUDA Toolkit отдельно на хост устанавливать не требуется.

Проверьте в терминале сервера:

```bash
nvidia-smi
docker info
docker compose version
python3 --version
git --version
```

Все команды должны выполняться без ошибок. Если `docker info` сообщает
`permission denied`, администратор должен настроить доступ к Docker;
после изменения группы пользователя нужно заново войти по SSH.

Если GigaAM/VoxCPM2 уже используют **эту же GPU**, остановите их из корня
`tts-stt` перед запуском Omni:

```bash
docker compose -f docker-compose.yaml -f docker-compose.gpu.yaml stop gigaam voxcpm2
```

Это освобождает GPU, но временно выключает старые API распознавания и синтеза.

## 2. Откройте нужную ветку и папку

Команды выполняются на сервере, где уже скачан этот репозиторий:

```bash
cd /путь/к/tts-stt
git switch feat/qwen3-omni-speech-to-speech
cd speech-to-speech
cp -n .env.example .env
```

Ветка и её коммит должны быть доставлены на сервер до этого шага. Если у вас
архив проекта, откройте папку `speech-to-speech` из архива; Git тогда не нужен
для переключения ветки.

Для однокарточного сервера менять `.env` не нужно. При необходимости откройте
его текстовым редактором:

```bash
nano .env
```

- `GPU_ID=0` — номер карты из `nvidia-smi`.
- `S2S_PORT=8091` — порт нового сервиса, старые порты 8000/8001 не заняты им.
- `S2S_API_PORT=8002` — HTTP API для приложения: загрузка файла и голосовой ответ.
- `S2S_API_BIND=0.0.0.0` — API доступен по адресу сервера; `127.0.0.1` ограничивает доступ сервером.
- `S2S_DATA_DIR=./data` — место хранения весов. Для отдельного диска укажите,
  например, `/srv/qwen3-omni`. Docker хранит образы на своём диске отдельно.
- `HF_TOKEN` обычно оставьте пустым. Заполняется только при необходимости
  авторизации Hugging Face; не отправляйте этот файл другим людям.

Внутри контейнера выбранная карта всегда получает номер 0 — это нормально,
даже если на сервере выбран `GPU_ID=1`.

## 3. Проверьте сервер и запустите

Сначала лёгкая проверка без скачивания модели:

```bash
./run.sh check
```

Ожидаемый результат: `Проверка хоста пройдена`. При ошибке исправьте указанную
причину. Проверка намеренно останавливает запуск на неподходящей карте,
занятой GPU, старом драйвере или недостаточном диске.

Затем выполните:

```bash
./run.sh install
```

Если окно доступа к GPU ограничено, образ и веса можно подготовить **заранее**
на этом же Linux-сервере без GPU:

```bash
./run.sh build
./run.sh test
./run.sh prepare
```

После подключения свободной GPU выполнить `./run.sh deploy`: он использует
готовые образ и веса, проверяет карту, запускает сервис и выполняет аудиотест.
Для этих подготовительных команд всё равно нужны место на диске и интернет.
`test` проверяет HTTP API и ffmpeg с заглушкой движка в отдельной Docker-сети;
настоящий инференс модели проверяется позже командой `verify` на GPU.

Скрипт соберёт образ, проверит вычисления CUDA внутри контейнера, скачает
закреплённый checkpoint, проверит наличие всех трёх частей модели и полноту
файлов весов, затем запустит сервис. В конце он создаст озвученную фразу,
передаст полученный звук обратно модели и потребует текстовый и звуковой ответ.
Затем тот же вход отправляется через HTTP API; результат сохраняется
в `output/api-answer.wav`.

Первый запуск долгий: скачиваются большой образ и 26,3 ГБ весов, компилируются
GPU-ядра. Не закрывайте SSH-сессию; удобно выполнять команду в `tmux`.
На ожидание запуска API отведено до 30 минут **после** сборки и скачивания.

Успешное завершение выглядит так:

```text
Сервис запущен, техническая проверка аудио пройдена. Прослушайте output/test-answer.wav.
```

Если загрузка весов прервалась, повторите `./run.sh prepare`, затем
`./run.sh start` и `./run.sh verify`: уже скачанные файлы используются из кеша.
После успешного запуска повторно выполнять `install` не нужно.

## 4. Прослушайте ответ и задайте свой вопрос через API

После установки доступны `http://SERVER:8002/docs`, `/health` и
`POST /speech-to-speech`, как у остальных сервисов репозитория.
Например, на сервере:

```bash
curl --fail-with-body http://localhost:8002/health
curl --fail-with-body -X POST http://localhost:8002/speech-to-speech \
  -F 'file=@question.wav' --output output/my-answer.wav
```

Для вызова с другого компьютера замените `localhost` на адрес сервера.
API принимает также MP3, OGG, WebM и FLAC и сам преобразует их.
Текст вместе с аудио возвращается при `?response_format=json`.
Примеры, ошибки и контракт описаны в [API.md](API.md).

Скачайте с сервера `speech-to-speech/output/test-answer.wav` через SFTP
или интерфейс файлов вашего сервера и прослушайте. Текст ответа находится
рядом в `test-answer.txt`, время запроса — в `test-answer.json`.

Автотест подтверждает прохождение аудио через модель и наличие непустого
звука. Качество русского языка и правильность смысла оцениваются прослушиванием.

Для собственного вопроса достаточно отправить запись до 30 секунд и 10 MiB
командой `curl` выше. Предварительное преобразование для HTTP API не требуется.
Низкоуровневый `client.py` обращается напрямую к Omni и используется автотестом;
для приложения используйте [HTTP API](API.md).

На первом этапе выполняйте запросы по одному; HTTP-обёртка вернёт 429 при занятости. Этот комплект принимает
завершённые записи и возвращает готовый WAV; микрофонный интерфейс, история
диалога, VAD и прерывание ответа в него не входят.

## 5. Управление

Выполняйте из папки `speech-to-speech`:

| Команда | Действие |
| --- | --- |
| `./run.sh status` | Показать контейнер и его состояние |
| `./run.sh logs` | Показать текущие логи; Ctrl+C закрывает просмотр |
| `./run.sh verify` | Повторить проверку голосового тракта |
| `./run.sh stop` | Остановить новый сервис; веса сохраняются |
| `./run.sh start` | Запустить с уже скачанными весами |
| `./run.sh deploy` | Проверить и запустить заранее подготовленный комплект |
| `./run.sh doctor` | Собрать диагностику в `reports/` |
| `./run.sh test` | Проверить HTTP-обёртку без GPU и весов (после сборки образа) |

Движок модели не настроен на автоматический запуск после перезагрузки сервера:
выполните `./run.sh start`, затем `./run.sh verify`. При сбое он также
не перезапускается бесконечно — причина остаётся доступна в логах.

Прямое API движка Omni доступно только на самом сервере: `http://127.0.0.1:8091`.
Проверить: `curl --fail http://127.0.0.1:8091/health`.
Для доступа со своего компьютера откройте SSH-туннель:

```bash
ssh -L 8091:127.0.0.1:8091 USER@SERVER
```

После этого скопируйте `client.py` на свой компьютер и запускайте его локально
с локальным WAV. Для доступа через backend нужен `POST /v1/chat/completions`,
имя модели `qwen3-omni-speech`; готовый запрос есть в `client.py`.
Одна замена старого STT URL не подключает диалоговый API.

## Если возникла ошибка

| Сообщение / ситуация | Действие |
| --- | --- |
| GPU занята | Посмотреть `nvidia-smi`, остановить использующие эту карту сервисы |
| Драйвер слишком старый | Администратор обновляет драйвер; после перезагрузки повторить `check` |
| Docker не видит GPU / `could not select device driver` | Настроить NVIDIA Container Toolkit и перезапустить Docker |
| Ошибка скачивания / HTTP 429 | Проверить интернет/авторизацию, повторить `prepare`; кеш сохраняется |
| Порт занят | Если это уже запущенный Omni — `verify`; иначе изменить `S2S_PORT` |
| `unhealthy` / таймаут / OOM | `./run.sh doctor`, проверить `reports/omni.log` и `reports/gpu.txt` |
| Есть текст, но нет WAV | Автотест считается неуспешным; проверить загрузку Talker и Code2Wav |
| Ошибка формата входного аудио | Проверить, что файл содержит исправную аудиозапись поддерживаемого формата |

При ошибке не удаляйте `data/`: там скачанные веса. Для разбора нужны
`reports/`, `output/gpu-check.json`, вывод команды и сведения о сервере.
Локально сохраняемый `.env` с токеном передавать не нужно.

## Состав папки

`compose.yaml` запускает Omni и HTTP-обёртку без доступа к GPU; `Dockerfile` собирает окружение;
`deploy.yaml` размещает три стадии на одной GPU; `versions.json` задаёт версию
модели; `run.sh` выполняет шаги установки; `runtime.py` проверяет и запускает
модель; `host_check.py` проверяет сервер; `api.py` принимает HTTP-запросы;
`client.py` отправляет аудио напрямую движку и сохраняет
ответ. Технические основания и границы проверки описаны в [SOURCES.md](SOURCES.md).
