# Запуск Qwen3-Omni рядом с STT/TTS на NVIDIA A100 (80 ГБ)

На одной видеокарте **NVIDIA A100 80 ГБ** одновременно работают три независимых сервиса на разных портах:
- **`8000`** — `GigaAM` (STT: распознавание речи)
- **`8001`** — `VoxCPM2` (TTS: синтез речи)
- **`8002`** — `Qwen3-Omni` (голосовой диалог `POST /speech-to-speech` и текстовая LLM `POST /chat`)

Память карты 80 ГБ делится так: **70% (~56 GiB)** выделено под три стадии `Qwen3-Omni` (`Intel/Qwen3-Omni-30B-A3B-Instruct-int4-AutoRound`), а **30% (~24 GiB)** остаётся для `GigaAM`, `VoxCPM2` и системного запаса. Остановка или перезапуск `Qwen3-Omni` не затрагивает контейнеры `GigaAM` и `VoxCPM2`.

**Границы проверки:** Docker-образ, зависимости, 39 автотестов и HTTP API проверены локально и в CI. Команда установки включает реальный тест модели на GPU; успешный запуск на сервере фиксируется только после его прохождения.

---

## 1. Требования к серверу

Подробные требования для администратора — в [ADMIN.md](ADMIN.md). Перед стартом убедитесь, что на сервере:
- **GPU:** 1× NVIDIA A100 80 ГБ (или H100 80 ГБ), режим MIG отключён, свободно **не менее 75% VRAM (~60 GiB)** перед стартом Qwen.
- **Драйвер NVIDIA:** **`580.95.05` или новее** (внутри контейнера используется CUDA 13.0.2).
- **ОС, RAM и диск:** Ubuntu 24.04 x86_64, **128 ГБ RAM**, минимум **80–150 ГБ** свободного места на диске.
- **ПО:** Docker Engine, Docker Compose v2, NVIDIA Container Toolkit, `git`, `python3`, `curl`.

## 2. Пошаговый запуск с нуля

### Шаг 1. Обновите репозиторий и перезапустите STT/TTS
Подключитесь к серверу по SSH и обновите код в корне репозитория `tts-stt`:

```bash
cd /путь/к/tts-stt
git checkout master
git pull origin master
```

Пересоберите и перезапустите `gigaam` и `voxcpm2` из корня репозитория (в актуальной версии они автоматически очищают кэш видеопамяти после запросов, чтобы освобождать место для Qwen):

```bash
docker compose -f docker-compose.yaml -f docker-compose.gpu.yaml up -d --build gigaam voxcpm2
```

> Если `gigaam` и `voxcpm2` уже давно работали и удерживают кэш PyTorch в VRAM, перед установкой Qwen сбросьте его командой:
> ```bash
> docker compose restart gigaam voxcpm2
> ```

### Шаг 2. Запустите установку Qwen3-Omni одной командой
Скрипт полностью автономен и не требует сторонних утилит (включая `tmux`). Запустите его из каталога `speech-to-speech`:

```bash
cd speech-to-speech
./run.sh check
./run.sh install
```

> *Совет: скачивание весов (26,3 ГБ) занимает 5–15 минут в зависимости от скорости интернета. Не закрывайте SSH-сессию во время работы команды. Если есть риск обрыва связи, можно запустить установку в фоне: `nohup ./run.sh install > install.log 2>&1 &` (или использовать `tmux` / `screen`, если они уже установлены).*

Скрипт `./run.sh install` сам выполняет все шаги:
1. Проверяет сервер, свободную видеопамять (>= 75%), драйвер, диски и порты (`8002`, `8091`).
2. Собирает закреплённый Docker-образ и проверяет вычисления CUDA / BF16 внутри контейнера.
3. Скачивает веса модели в `data/` и проверяет целостность всех 13 файлов.
4. Запускает движок модели (`omni`) и HTTP API (`api` на порту `8002`), дожидается готовности (до 30 минут).
5. Выполняет контрольные запросы: проверяет текстовую ручку `/chat` и голосовую ручку `/speech-to-speech`.

**Установка завершена успешно**, когда команда вернула код `0` и вывела:

```text
Сервис запущен, техническая проверка аудио пройдена. Прослушайте output/test-answer.wav.
```

Результаты тестовых запросов сохраняются в `output/`:
- `api-chat-answer.txt` — ответ текстового LLM (`POST /chat`);
- `test-answer.wav` и `test-answer.txt` — голосовой ответ и его текст напрямую от движка;
- `api-answer.wav` — голосовой ответ через HTTP API (`POST /speech-to-speech`).

Прослушайте WAV: речь должна быть разборчивой и соответствовать тексту.

## 3. Проверка и использование API

Интерактивная документация (Swagger UI): **`http://АДРЕС_СЕРВЕРА:8002/docs`**. Полный контракт описан в [API.md](API.md).

### Проверка готовности всех трёх сервисов
```bash
curl --fail http://localhost:8000/health
curl --fail http://localhost:8001/health
curl --fail http://localhost:8002/health
```

### Голосовой диалог Qwen3-Omni (`POST /speech-to-speech`)
Принимает WAV, MP3, OGG, WebM и FLAC (до 30 секунд и 10 MiB), автоматически конвертирует аудио и возвращает WAV-файл с голосовым ответом:

```bash
curl --fail-with-body -X POST http://localhost:8002/speech-to-speech \
  -F 'file=@output/test-question.wav' --output output/example-answer.wav
```

Чтобы получить **текст и аудио (base64)** в одном JSON, добавьте `?response_format=json`:
```bash
curl --fail-with-body -X POST 'http://localhost:8002/speech-to-speech?response_format=json' \
  -F 'file=@output/test-question.wav'
```

### Текстовый чат с LLM без генерации аудио (`POST /chat`)
```bash
curl --fail-with-body http://localhost:8002/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Сколько будет два плюс два?"}]}'
```

## 4. Команды управления (из папки `speech-to-speech`)

- `./run.sh status` — состояние контейнеров Qwen.
- `./run.sh logs` — просмотр логов в реальном времени (`Ctrl+C` для выхода).
- `./run.sh verify` — повторить приёмочные запросы к модели.
- `./run.sh stop` — остановить Qwen (`GigaAM` и `VoxCPM2` продолжают работать; скачанные веса в `data/` сохраняются).
- `./run.sh start` — быстро запустить сервис с уже скачанными весами (после остановки или перезагрузки сервера).
- `./run.sh doctor` — собрать логи и диагностику GPU в папку `reports/`.

> **Запуск из корня репозитория:**
> Для прямого управления контейнерами Qwen без перехода в каталог `speech-to-speech` можно использовать отдельный compose-файл:
> ```bash
> docker compose -f docker-compose.qwen.yaml up -d --build
> docker compose -f docker-compose.qwen.yaml ps
> docker compose -f docker-compose.qwen.yaml logs -f
> docker compose -f docker-compose.qwen.yaml down
> ```

## 5. Частые ошибки и их решение

| Ошибка / ситуация | Причина и что сделать |
| :--- | :--- |
| **`Для запуска Qwen рядом с STT/TTS нужно 60.0 GiB свободной VRAM; доступно ...`** | Соседние `gigaam`/`voxcpm2` удерживают кэш видеопамяти. Выполните из корня репозитория:<br>`docker compose restart gigaam voxcpm2`<br>и заново запустите `./run.sh install`. |
| **`Драйвер ... слишком старый. Нужен 580.95.05 или новее`** | Образ Qwen собран на CUDA 13.0.2. Администратор должен обновить драйвер NVIDIA на хосте до версии `>= 580.95.05` и перезагрузить сервер. |
| **`На общем диске весов и Docker нужно 80 GiB свободно`** | Не хватает места на диске. Очистите неиспользуемые образы (`docker system prune -af`) или укажите путь к другому диску в `.env` (`cp -n .env.example .env`, параметр `S2S_DATA_DIR=/mnt/disk/qwen`). |
| **`Порт 8002 (или 8091) занят`** | Если Qwen уже запущен — проверьте `./run.sh status` и `./run.sh verify`. Если порт занят другим процессом — измените `S2S_API_PORT` в `.env`. |
| **Обрыв сети / ошибка при скачивании весов с Hugging Face** | Просто запустите `./run.sh install` повторно — уже скачанные файлы сохранены в `data/` и докачаются с места обрыва. При лимитах Hugging Face укажите `HF_TOKEN` в `.env`. |
| **Контейнер `omni` не запустился (`unhealthy` / `OOM`)** | Выполните `./run.sh doctor` и проверьте `reports/omni.log` и `reports/gpu.txt`. Передайте каталог `reports/` администратору. |
| **API возвращает `HTTP 429 (Модель занята)`** | Сервис обрабатывает 1 запрос одновременно (общий слот для `/speech-to-speech` и `/chat`). Повторите запрос через 5 секунд. |
