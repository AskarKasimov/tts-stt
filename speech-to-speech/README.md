# Запуск Qwen3-Omni: инструкция для исполнителя

Сервис принимает голосовой вопрос и возвращает голосовой ответ. Отдельная
ручка `/chat` принимает текст и возвращает текст. Используется готовый
INT4 checkpoint; версии модели и программного окружения уже закреплены.

**Границы проверки:** Docker-образ, зависимости и HTTP API проверены локально
и в CI. Инференс на A100/H100 пока не проверен. Команда установки включает
реальный тест модели; успешный запуск на сервере фиксируется только после него.

## 1. Получить подготовленный сервер

Передайте администратору [требования к серверу](ADMIN.md).
Используется существующий сервер STT/TTS с одной NVIDIA GPU 80 ГБ,
Ubuntu 24.04 x86_64, RAM 128 ГБ,
150 ГБ свободного места и драйвер NVIDIA от 580.95.05.
Администратор подготавливает Docker и доступ к GPU до передачи сервера исполнителю.

Используйте переданную версию репозитория `tts-stt`, содержащую эту папку.
Сервер должен быть подготовлен по указанным требованиям; подбирать версии
CUDA, PyTorch и библиотек в ходе установки не требуется.

## 2. Выполнить одну команду установки

Из корня репозитория:

```bash
cd speech-to-speech
./run.sh install
```

Настройки по умолчанию уже заданы: GPU 0 — та же карта, которую используют
GigaAM и VoxCPM2 на однокарточном сервере, HTTP API на порту 8002.
Существующие STT/TTS продолжают работать в своих контейнерах.
Бюджет движков Qwen — 70% VRAM (примерно 56 GiB на карте 80 GiB),
оставшиеся 30% планируются для STT/TTS и общего резерва.
Для старта Qwen нужно не менее 75% свободной VRAM: 70% на движки и запас
на инициализацию. Если `GigaAM`/`VoxCPM2` уже работали и удерживают кэш PyTorch,
перед установкой сбросьте его командой `docker compose restart gigaam voxcpm2`
из корня репозитория. Пики совместной нагрузки требуют серверной проверки.
Создавать или редактировать `.env` для этого сценария не требуется.

Скрипт сам выполняет все шаги:

1. Проверяет сервер, свободную видеопамять, драйвер, диски и порты.
2. Собирает закреплённый Docker-образ и проверяет CUDA внутри контейнера.
3. Скачивает нужную версию весов и проверяет их состав и размеры.
4. Запускает модель и HTTP API, дожидается готовности.
5. Проверяет настоящий голосовой тракт, текстовую ручку и голосовую ручку API.

Первый запуск скачивает большой образ и 26,3 ГБ весов. Дождитесь завершения
команды; время зависит от сети и прогрева GPU. После скачивания и сборки
ожидание готовности сервиса ограничено 30 минутами. Таймаут каждого тестового
запроса — до 15 минут, включая первый прогрев.

**Установка завершена успешно**, только если команда вернула код 0 и вывела:

```text
Сервис запущен, техническая проверка аудио пройдена. Прослушайте output/test-answer.wav.
```

Результаты реальных запросов находятся в `output/`:

- `api-chat-answer.txt` — ответ текстового LLM;
- `test-answer.wav` и `test-answer.txt` — голосовой ответ и его текст;
- `api-answer.wav` — голосовой ответ через HTTP API.

Прослушайте WAV: речь должна быть разборчивой и соответствовать тексту.
Автоматический тест проверяет наличие текста и непустого аудио; смысл и
естественность речи оцениваются прослушиванием.

## 3. Использовать API

Интерактивная документация: `http://АДРЕС_СЕРВЕРА:8002/docs`.

Текстовый запрос (команда выполняется на сервере):

```bash
curl --fail-with-body http://localhost:8002/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Сколько будет два плюс два?"}]}'
```

Голосовой запрос с уже созданной тестовой записью:

```bash
curl --fail-with-body http://localhost:8002/speech-to-speech \
  -F 'file=@output/test-question.wav' --output output/example-answer.wav
```

Для своего вопроса замените путь после `@` на вашу запись. Поддерживаются
WAV, MP3, OGG, WebM и FLAC, до 30 секунд и 10 MiB. Формат преобразуется
автоматически. Ответ — WAV; текст вместе с аудио доступен через
`?response_format=json`. Полный контракт: [API.md](API.md).

## Управление и обращение к администратору

- `./run.sh status` — состояние сервисов.
- `./run.sh verify` — повторить приёмочные запросы к модели.
- `./run.sh stop` — остановить сервисы; скачанные веса сохраняются.
- После перезагрузки сервера: `./run.sh start`, затем `./run.sh verify`.

Если установка завершилась с ошибкой, передайте администратору каталог
`reports/` и вывод команды. Установка в этом случае не считается принятой.
Скачанные веса находятся в `data/` и сохраняются для повторного запуска.
